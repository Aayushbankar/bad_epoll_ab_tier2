487	 * As described in commit 0ccf831cb lockdep: annotate epoll
488	 * the use of wait queues used by epoll is done in a very controlled
489	 * manner. Wake ups can nest inside each other, but are never done
490	 * with the same locking. For example:
491	 *
492	 *   dfd = socket(...);
493	 *   efd1 = epoll_create();
494	 *   efd2 = epoll_create();
495	 *   epoll_ctl(efd1, EPOLL_CTL_ADD, dfd, ...);
496	 *   epoll_ctl(efd2, EPOLL_CTL_ADD, efd1, ...);
497	 *
498	 * When a packet arrives to the device underneath "dfd", the net code will
499	 * issue a wake_up() on its poll wake list. Epoll (efd1) has installed a
500	 * callback wakeup entry on that queue, and the wake_up() performed by the
501	 * "dfd" net code will end up in ep_poll_callback(). At this point epoll
502	 * (efd1) notices that it may have some event ready, so it needs to wake up
503	 * the waiters on its poll wait list (efd2). So it calls ep_poll_safewake()
504	 * that ends up in another wake_up(), after having checked about the
505	 * recursion constraints. That are, no more than EP_MAX_POLLWAKE_NESTS, to
506	 * avoid stack blasting.
