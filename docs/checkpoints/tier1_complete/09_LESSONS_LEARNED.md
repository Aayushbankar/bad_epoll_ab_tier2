# Lessons Learned

- **AT&T vs Intel Disassembly Interpretations Can mislead Triage Efforts.** Initial triage of the stack pivot panic incorrectly blamed differences between `objdump` AT&T syntax vs standard Intel notation. We wasted significant time diagnosing a valid JOP payload (`push %rdx` vs `push %rdi`) when empirical memory forensics proved the registers aligned correctly.
- **Always Validate DBase Provenance against Local Target Hashes.** A pre-compiled `.kxdb` file should never be trusted when executing against a manually compiled `vmlinux`, even if identical source repositories and `.config` are utilized. Slight compiler alterations (such as Fedora GCC vs upstream GCC) can shift block addresses by hundreds of bytes.
- **Python Serialization Incompatibilities Impact Automation Pipelines.** Advanced object-oriented programming frameworks (like `angrop` nested subclass structures) can fail randomly during standard multiprocess operations due to Python's `pickle` engine scope limits. These pipeline breaks must be manually traced and repaired natively instead of relying on brute-force re-executions.
- **Userspace Execution Demands Valid Controlling Terminals in Baremetal Simulators.** A successful ret2usr hijack mapping over `PID 1` (`/init`) is inherently fragile. If the targeted userspace binary (like `/bin/sh`) fails to execute or cleanly hits an EOF and returns `0` due to a missing interactive terminal hook inside a QEMU wrapper, the Linux kernel will instantly kill the process tree and throw a system panic, successfully masking a functionally complete exploit.
